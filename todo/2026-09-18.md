# 2026-09-18 — Initial import to GitHub

Walkthrough Studio existed on exactly one machine, untracked, with roughly 55 MB of
capture artifacts generated this morning that had no second copy anywhere. This commit
is the backup, and the start of the repository that the Walkthrough pattern will be
presented from.

## What We Built

- First git history for the project. 172 files: the pnpm workspace, the `hub` app, the
  dual Claude/Codex plugin packaging, the docs, and the captured walkthrough artifacts
  under `apps/hub/public/walkthroughs/`.

## Key Decisions

- **Private on creation.** The Walkthrough pattern is meant to be public by the
  AI Tinkerers Doha Round 3 talk (Mon 2026-09-21) so the audience can read the source
  behind the demo, but making a repository public is not reversible in any meaningful
  sense. Imported private; the flip to public is a deliberate, separate step.
- **Artifacts are committed, not ignored.** `apps/hub/public/walkthroughs/` holds the
  real Wikipedia capture run — screenshots, catalog, personas. It is the evidence the
  pattern works on somebody else's product, not scratch output, so it belongs in the
  repository. Scratch space (`.tmp-*`, `test-results/`, `playwright-report/`,
  `*storageState.json`) stays ignored by the existing `.gitignore`.
- **`.claude/skills/walkthrough` stays a symlink.** It is relative
  (`../../plugins/walkthrough/skills/walkthrough`), so it resolves inside a fresh clone
  and the skill has exactly one source of truth.

## Known Issue Carried In

- The catalog schema here (`surfaceStatus: {desktop, mobile}`, `location`,
  `capturedAgainst`) is a newer generation than the one Openstage writes
  (`desktopStatus`/`mobileStatus`, `route`). The two cannot currently be read by the same
  dashboard. Reconciling them is what stands between Openstage and a real walk.

## Header alignment — two silent CSS failures, not one nudge

The breadcrumb read "Walkthrough › Wikipedia" with the crumb sitting visibly lower than
the wordmark and each chevron hugging the label to its right. Measured in the browser
rather than eyeballed: **baselines 4.1px apart, gaps 12px before each chevron and 6px
after.** Both causes were classes that were never in effect.

- **`tailwind-merge` was deleting `leading-none` from the wordmark.** `cn()` is
  `twMerge`, which files `leading-*` and an arbitrary `text-[...]` in the same conflict
  group, so `cn("font-serif leading-none …", "text-[0.9375rem]")` shipped without the
  leading. The wordmark inherited the body's 1.6 — a 24px line box around 15px type.
  Nothing warns you; the class is simply absent from the DOM. Folded the line-height
  into the size utility (`text-[0.9375rem]/[1]`) so there is only one class to merge.
- **The logo `<a>` was a block, so it wrapped the lockup in a line box.** The
  `inline-flex` lockup then baseline-aligned to that line box's strut, which is sized by
  the inherited leading and nothing in the lockup. The mark and wordmark sat 3.5px above
  the header's centre while the breadcrumb sat exactly on it. `flex items-center` on the
  anchor removes the inline formatting context and the strut with it.
- Gaps equalised to 8px on both sides of every chevron, so the separator sits between
  the two labels instead of belonging to one.

Verified: mark, wordmark, chevron and crumb now all report a box centre of exactly 28px
in a 56px header, on the two-crumb and three-crumb pages and on the home lockup.

**The lesson worth keeping:** when a Tailwind class appears to do nothing, check that it
is in the DOM before changing the value. Two rounds here were spent adjusting numbers on
a class that `twMerge` had already thrown away.
