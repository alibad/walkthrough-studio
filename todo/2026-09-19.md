# 2026-09-19 — Say what it needs, and prove it works

## What We Built

**You can now find out whether this thing is configured without running a walk to
discover it.** `pnpm doctor` reports every capability the system uses, which
provider is satisfying each one, and what specifically breaks without it. It
exits 1 only when something genuinely required is missing — a machine with no
image provider is not broken, it just publishes monograms instead of portraits.

**"Set" and "working" are now different answers.** A revoked key, a rotated key
and a key with a trailing newline all look identical to a presence check, and
every one of them fails at the first real request — which in this repo is six
minutes into a walk, at the art step. The doctor makes one real call per
provider against the free list-models endpoint, and checks in the same call that
the account can actually reach the model the scripts are about to name.

**A new page at `/setup`** renders the same report the command prints: what each
capability is for, what satisfies it, what degrades without it, and — on a local
`pnpm dev` — a button that runs the live check and shows the verdict per
provider. The page holds no state of its own; it shells out to `pnpm doctor`, so
the page and the command cannot disagree about whether a key works.

## Key Decisions

**A key is only needed for what the agent cannot do itself.** The walk is driven
by an agent, and an agent is already a model — it writes every persona bio, step
description and finding with no API key at all. Paying an API to write those
sentences is paying twice for the same sentence. The real gaps are the two
artifacts a coding agent cannot return from a tool call: a PNG of a face and an
MP3 of a voice. Those, and only those, are what a provider is for.

**So illustration is now host-first.** A host that can generate an image writes
the plate directly and no provider is configured at all. The skill now asks that
question before reaching for `pnpm persona:art`, and says plainly that a missing
provider is not a blocker and is not a reason to borrow a key from another
repository. `WALKTHROUGH_IMAGE_PROVIDER=host|api|none` settles it outright.

**Host detection is a hint and never a claim.** Claude Code exports
`CLAUDECODE=1` to every child process, so it is reliably identifiable. Codex
exports `CODEX_SANDBOX` only when sandboxed — confirmed by reading the strings
of the shipped binary rather than assuming — so its *absence* proves nothing.
Nothing in the system infers a capability from a missing variable, and the page
says so where a reader can see it.

**The deployed hub deliberately reports less than the local one.** A public page
saying "API key: set ✓" publishes the configuration state of a machine to
anyone who finds the route, and implies the server holds a key. It does not, and
should not — nothing in the hub ever calls a model. In production the page
renders the model and the verify route is a 404, which is also the literal
truth. Verified against a real production build, not assumed.

**Three states for a capture backend, not two.** "The Android SDK is installed"
and "Android can be captured right now" are different claims. A toolchain that
is present with nothing attached or booted now reports as partial with the
missing step named, rather than as ready.

## What We Fixed

- The registry described Openstage as living at `present.openstage.humanquest.net`.
  That host does not resolve; the deck platform is at `present.humanquest.net`.
- The skill and the capability model both described the no-art fallback as a
  "lettered monogram". That was the old behaviour — the giant initial was
  replaced earlier with a typographic panel carrying the persona's entry point
  and walked-journey count. Both now describe what actually renders.
- Reading `../../.env.local` from the hub made Turbopack give up on tracing and
  pull the whole monorepo into the serverless function. Every path the hub reads
  now stays inside the app, and the environment is read only by the scripts that
  need it.
- Node's `fetch` reports every transport failure as the same three words. The
  credential check now unwraps the cause, so "you typed the endpoint wrong" and
  "the network is down" stop looking like the same problem.

## Notes

- Nothing in this repo prints a key — not a prefix, not a length. A fingerprint
  of a key is still a fact about a key, and this output gets pasted into issues.
- At the time of writing this section the machine had no `.env.local` at all, so
  illustration and the Openstage `ADMIN_PASSWORD` were the two reported gaps.
  The first of those was closed later the same day — see below. Narration worked
  throughout, on the local Kokoro engine.

# Later the same day — one provider, one key

## What We Fixed

**Azure is gone.** Generating a single portrait used to need four correct values
— an endpoint, a key, an API version and a per-capability *deployment name* —
and three of them failed silently when wrong. It is now one variable,
`OPENAI_API_KEY`, covering images, text and speech. Every script, document and
page that mentioned Azure has been rewritten; `grep -i azure` returns nothing
outside this changelog.

**The persona art exists.** Openstage's Reader now has a portrait, a
scene-setter and three moment plates, generated and committed. The persona card
was the thing that looked broken, and it was the oldest outstanding complaint.

## Key Decisions

**Model ids are checked, not remembered.** `GET /v1/models` with the real key
showed `gpt-image-2.5` had superseded `gpt-image-2` two weeks ago — the notes
saying otherwise were five weeks old and already wrong. Both 2.5 tiers were
called with this repo's exact request shape before either was made the default,
so the default is a verified value. `pnpm doctor` now re-checks on every run
that the configured key can reach the configured model, and
`OPENAI_IMAGE_MODEL` / `OPENAI_TEXT_MODEL` override it without touching code.

**`generate-creatives.mjs` lost its private copy of the API.** It had its own env
loader and its own HTTP calls, so it drifted from `lib/models.mjs` the moment
the image line moved. It now calls the shared helper like everything else.

## What We Fixed, continued

**Generated plates were inventing words.** The first Reader moment shot came
back with a booklet titled "Community Health Forum" — clean, legible, and a
claim about a product that has nothing to do with presentations. The house style
had always forbidden text, but only in the preamble, and the scene writer was
separately being *asked* for "one specific object in frame" with nothing
stopping it choosing a titled book or a branded cup.

Both ends are fixed: the scene writer is told to pick objects whose identity is
a shape rather than a name, and the no-letterform rule is restated after the
description where it is read last. Regenerated — three plates, no letterforms,
same person throughout.

## Notes

- The key was copied from `tinkerer-presenter` at the owner's request. It lives
  in `.env.local`, which is gitignored, and no command in this repo prints it.
- Narration now has two working engines. OpenAI TTS self-selects; local Kokoro
  remains the fallback so a clone with no account still renders a story video.

# Third pass — what a stranger would see

Reviewed the deployed hub as a first-time visitor rather than as its author.
Four things were wrong; three are fixed here and the fourth is a decision, not
a bug.

## What We Fixed

**A home directory was published.** The Openstage page printed
`/Users/<name>/Code/GitHub/openstage` under "Checkout" — truncated in the UI,
whole in the page source — and `projects.json` and `walk-openstage.mjs` both
carried the absolute path in committed source. Registry paths are now resolved
against the repository root, so `../openstage` says the same thing to every
machine that has the sibling checkout and says nothing to a stranger.

The Checkout row itself is now local-only. It answers "where do I run the walk
from", which is a question for the person running it and for nobody else.

**A side effect worth having:** because the relative path resolves on this
machine, the drift card now actually measures. It reads "Fresh · 1d ago" where
it used to say it could not tell.

**The drift card was addressing the maintainer in front of the audience.** On
every published page it read "Set `codebase.local` in `projects.json` to a git
checkout and this card starts working" — an instruction the reader cannot act
on, describing a state that can never be fixed in production, because drift is
measured by diffing a repo that a deployed hub does not have. The published
copy now states the true thing: drift is measured on the machine that runs the
walk, so this copy reports what was captured and when.

**The homepage chart was illegible on a phone.** Measured rather than
eyeballed: the chart is a fixed 1000x700 viewBox scaled to the column, so at
375px it renders at 0.375 and its 17px labels paint at 6.4px — the whole map
32px wide. It was not blank, which is what made it worse; it read as a
rendering failure rather than as a small map.

Narrow viewports now land on the list view, which answers the same question
without a spatial metaphor. The toggle still offers the chart, an explicit
choice is still remembered, and the responsive default deliberately does not
write to localStorage so it never becomes sticky on a later desktop visit. The
chart container also matches the viewBox ratio below `lg`, removing 154px of
dead paper.

## Still Open — a decision, not a defect

**Both repositories are private.** Every install path on `/use` —
`/plugin marketplace add`, `git clone`, the marketplace install — 404s for
anyone who is not the owner, as do the repo card and the Openstage repository
link. The entire adoption surface is currently unreachable. Making
`walkthrough-studio` public is what turns this from a demo into something
someone can run; if `openstage` stays private, the honest move is to drop its
repository link rather than publish a dead one.
